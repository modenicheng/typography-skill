# L1 · 原则：排版的秩序来自比较，不是来自装饰

这一层不提供数值。它负责回答一个前置问题：**这个页面为什么看起来乱？** 数值在 L2，语言差异在 L3。如果层级本身是错的，换字号也救不回来。

## 1. 三个变量，而不是十个

一段文字在视觉上的「响度」由四件事决定，按影响力排序：

1. **字号**（size）—— 决定占据的面积。
2. **字重**（weight）—— 决定笔画的密度。
3. **颜色/对比**（color）—— 决定它跳出来的程度。
4. **留白**（space）—— 决定它和谁是一组。

新手只调第 1 项，于是得到「全是重点 = 没有重点」。成熟的做法是：**先固定字号，用 2、3、4 制造层级；只有当差异仍然不够时，才动字号，而且跳一级，不要挪 1px。**

> Refactoring UI 把这条放在第一章 *Hierarchy is Everything*：层级不是「让重要的更大」，而是「让不重要的更不明显」。两者的区别是：前者会不断加码，后者会不断做减法。

## 2. 为什么是 3–5 档

Ant Design 的字体规范明确建议：一个系统内（展示型页面除外）字阶控制在 3–5 种。原因不是美学，是**辨识阈值**：

- 相邻字号差异小于约 15% 时，读者感知不到「这是两个层级」，只会觉得「没对齐」。
- 差异大于约 15% 时，每一级都能被命名。
- 档位越多，命名越困难，Agent 越容易在 15/16/17 之间反复试探。

所以阶梯应该「跳」：12 → 14 → 16 → 20 → 28 → 48。相邻比值 1.17 / 1.14 / 1.25 / 1.4 / 1.71，越往上跳得越大。Ant 把这形容为「让字体像音符一样跳跃」——**要么同级，要么明显不同级，不要半级。**

## 3. 一致 ≠ 统一

设计系统常犯的错，是把「一致」理解成「所有页面长得一样」。真正的约束是：

- **同一角色，同一套值**（一致性）。
- **不同场景，允许不同密度**（适应性）。
- **例外必须显式**（可审计）。

因此本 skill 用「角色 × 密度」而不是「一套固定 px」：角色稳定，密度可变，例外写进 PR。

## 4. 排版颜色（typographic color）

一页文字在远处看是一块灰色。这块灰的深浅叫 typographic color，由字号、字重、行高、字距、行宽共同决定。

- 行高变小 → 灰色变深 → 更密、更「工作型」。
- 字重变大 → 灰色变深 → 更像标题。
- 字距变大 → 灰色变浅 → 更「展示型」，但超过 0.05em 会散。

中文的灰色天然比英文深：汉字笔画多、字身满。**同样的字号与字重，中文块看起来更黑。** 这就是为什么中文正文常常需要更大的行高来「透气」，也是为什么中文不宜再加字距。

## 5. 阅读 vs 扫描

两种行为，两套度量，不要混：

| | 阅读（reading） | 扫描（scanning） |
|---|---|---|
| 场景 | 文档、报告、长文、帮助中心 | 后台、表格、设置、仪表盘 |
| 行为 | 逐行连续读 | 找目标、比对、点按 |
| 字号 | 16–18px 起 | 13–14px 起 |
| 行高 | 1.6–1.8 | 1.4–1.6 |
| 行宽 | 30–36em | 由容器决定，允许更宽 |
| 层级 | 少而稳 | 多而浅 |
| 装饰 | 可以有余地 | 越少越好 |

后台页面用 18px 正文会显得松散；文档站用 14px 正文会显得廉价。**先判断用户在这个页面是读还是扫，再选密度。**

## 6. 间距是排版的一部分

字与字之间是字距，行与行之间是行高，块与块之间是间距。三者共同决定节奏。

- 用 4 的倍数：4 / 8 / 12 / 16 / 24 / 32 / 48 / 64。
- **靠近原则**：相关的东西靠近，不相关的东西拉开。标题与它下面的正文，间距应小于标题与上一段之间的距离（USWDS 建议上方至少是下方的 1.5 倍）。
- 不要用「均分」的 margin 处理所有块；那会让所有关系看起来一样远。
- 段落间距优先于首行缩进：Web 与 UI 用段间距，不用 2em 缩进（中文印刷传统里用缩进，但屏幕阅读与响应式布局更适合段间距）。

## 7. 对齐与行宽

- **左对齐是默认**。居中只用于短标题、封面、空状态，且不超过 2 行。
- **两端对齐只用于中文长文**，且要配合标点挤压；UI 短文本两端对齐会产生难看的字间空洞。
- **行宽 34em**：约 34 个汉字或 68 个拉丁字符。超过 40em，眼睛回行会丢行；小于 25em，断行过于频繁。
- 数字列右对齐，文本列左对齐；不要为了「整齐」把文本居中。

## 8. 光学修正

数学上的等距，眼睛看起来不一定等距。需要手工修正的地方：

- 标点：全角标点的字面偏向一侧，行首行尾要挤压或悬挂。
- 引号与括号：外侧需要更小的边距。
- 大字号：字距应收紧（拉丁），中文则保持 0。
- 图标与文字：视觉重心不在几何中心，需要 1px 级微调。
- 数字：表格用等宽数字（tabular），正文用比例数字（proportional）。

## 9. 用真实内容验收

Lorem ipsum 会掩盖所有问题。必须用：

- 最长的中文标签（8–12 字）。
- 中英混排的一句话（含产品名、数字、单位）。
- 极端数字（1,234,567.89 / -0.05% / 99.99%）。
- 空状态、错误状态、加载状态。
- 双语切换后的同一按钮（登录 / Log in）。

## 10. 反模式速查

| 反模式 | 为什么错 | 替代 |
|---|---|---|
| 一页 8 种字号 | 没有层级，只有噪声 | 5 个角色封顶 |
| 全部加粗表示重要 | 加粗失效，页面变吵 | 次要内容降色，重点用 500/600 |
| 中文正文 1.2 行高 | 汉字上下相撞 | 1.6–1.8 |
| 中文加 0.1em 字距 | 方块节奏被打散 | 0 |
| 用斜体强调中文 | 伪斜体，字形失真 | 字重/颜色/着重号 |
| 长文本居中 | 每行起点不同，回行困难 | 左对齐 |
| 12px 以下放正文 | 中文笔画粘连 | 12px 仅辅助信息 |
| 每个卡片都加边框和阴影 | 边界噪声 | 用留白分组 |

## 判断清单

写完一页，依次问：

1. 页面有几个字号？>5 就合并。
2. 有几个字重？>3 就合并。
3. 遮住颜色，只看灰度，层级还成立吗？
4. 把中文换成英文（或反之），布局还成立吗？
5. 去掉所有 border 和 shadow，分组还清楚吗？
6. 这一屏用户是在读还是在扫？当前的密度匹配吗？
